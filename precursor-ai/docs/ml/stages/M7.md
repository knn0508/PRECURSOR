# ML stage M7: Baselines and model training

Status: **NOT_STARTED**. Track: [ADR-0009](../../adr/ADR-0009-ml-development-track.md); status table: [ML_STATUS](../ML_STATUS.md). Executable brief: [Prompts.md](../../../Prompts.md) (section M7). Separate from the 10 roadmap phases; roadmap phases stay ML-free.

## Objective
Baselines and model training. See scope below.

## Scope
- Baselines first on identical splits and metrics: class prior, rainfall-threshold rule (evaluation only, inside `ml/`), regularised logistic regression.
- Approved families only: Random Forest, XGBoost, LightGBM; CNN on patches and temporal models (TCN/LSTM/GRU) only with a data-size justification and approved dependency.
- Nested spatial-block CV tuning with a stated budget, imbalance handling chosen on CV only, early stopping on validation folds, 3+ seeds, no tuning on the hold-out.
- Run tracking per the convention; artifacts in `ml/runs/<run_id>/`; nothing copied to `models/`.
- `ml/reports/M7_training.md`: full experiment table including failures, compute used, frozen candidate list.

## Out of scope
- Looking at final hold-out results, re-tuning afterwards, integration into backend or frontend.

## Gate
USER APPROVAL REQUIRED (compute and deep-model dependency before training; frozen candidates before M8). The next stage starts only when this stage's acceptance is met and any user stop above is recorded in ML_STATUS.

## Prerequisites
- M6 complete; compute and model-family approval.

## Acceptance (done when)
- Every model is compared against all baselines on the same splits.
- Training is reproducible for a fixed seed within tolerance; CV never mixes buffered neighbours.
- The user approved the frozen candidate list.
