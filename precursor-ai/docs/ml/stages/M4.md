# ML stage M4: Data cleaning and quality control

Status: **COMPLETED** (2026-11-15; see ml/reports/M4_cleaning.md). Track: [ADR-0009](../../adr/ADR-0009-ml-development-track.md); status table: [ML_STATUS](../ML_STATUS.md). Executable brief: [Prompts.md](../../../Prompts.md) (section M4). Separate from the 10 roadmap phases; roadmap phases stay ML-free.

## Objective
Data cleaning and quality control. See scope below.

## Scope
- Label cleaning: duplicates, bad coordinates, date errors, low or unrecorded location accuracy (excluded list with reasons), non-landslide event types, trigger types.
- Feature cleaning: fill values, artifacts, unwrapping errors, low-coherence quality masks, flagged outliers, unit and physical-range checks.
- Missing data quantified per feature, region and time; per-feature policy; imputation fitted on train only.
- Background sampling: outside 2x accuracy-radius buffer, same region, terrain-stratified, seeded, ratio recorded, pseudo-absence caveat.
- Automated leakage audit (spatial proximity, temporal order, future information, duplicates, target-derived features).
- Versioned, hashed cleaned dataset in `data/ml/processed/` with cleaning log; `ml/reports/M4_cleaning.md`.

## Out of scope
- Modelling, tuning, overwriting raw data.

## Gate
none. The next stage starts only when this stage's acceptance is met and any user gate above is recorded in ML_STATUS.

## Prerequisites
- M3 complete.

## Acceptance (done when)
- Every cleaning rule is documented, reversible and tested.
- Leakage audit passes (or failures are reported and fixed).
- Cleaned dataset has a hash and a row-level cleaning log.

## Implementation status
See ML_STATUS for the real state; record only real test output.

## Known limitations
Landslide inventories are incomplete and biased toward reported, accessible places; background samples are not proven stable; NISAR temporal depth is verified only in M1; any figure without recorded real output is NOT_VERIFIED.
