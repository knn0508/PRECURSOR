# ML stage M3: Preprocessing and harmonization

Status: **PARTIALLY_COMPLETED** (2026-11-15: approved data done; SAR and five factors unavailable, see ml/reports/M3_preprocessing.md). Separate from the 10 roadmap phases; roadmap phases stay ML-free.

## Objective
Preprocessing and harmonization. See scope below.

## Scope
- Inspect real SAR files first (HDF5 layout, units, identification fields); report Phase 3 adapter mismatches without patching them.
- Derive LOS displacement, coherence, velocity where justified; keep the sign-convention caveat.
- Common metric reference grid per region, alignment (bilinear continuous, nearest categorical), clip, NaN nodata.
- Static factors (terrain, land cover, soil, lithology, distance layers, NDVI) and dynamic factors (rainfall accumulations and antecedent indices, soil moisture, InSAR windows) time-indexed in UTC.
- Labels with event geometry, date and location-accuracy radius.
- Interim products in `data/ml/interim/` with manifest; `ml/reports/M3_preprocessing.md`.

- **User condition (2026-11-15):** the analysis grid cell size must be consistent with the ~5 km GLC location accuracy (no 30 m modelling with these points); aggregate static factors accordingly or label via the accuracy radius; document the choice.

- **User condition (2026-11-15):** CA, OR and WA geologic maps have different legends and attribute schemas; map them to one documented lithology class system before use and record the mapping and every unmapped class.

## Out of scope
- Modelling, feature selection, cleaning decisions (M4).

## Gate
none. The next stage starts only when this stage's acceptance is met and any user gate above is recorded in ML_STATUS.

## Acceptance (done when)
- Every layer is aligned to the recorded reference grid with documented resampling.
- Re-run is idempotent; CRS/transform and nodata propagation tests pass on real-data windows and labelled synthetic fixtures.
- Adapter findings recorded in PROJECT_STATUS known issues (report only).
